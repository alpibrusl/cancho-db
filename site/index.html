cancho-db

The database you can let agents write to.

A Postgres-compatible proxy whose commit path is verifiable. Every write becomes a signed, hash-chained commit that records who wrote, under which capability, and running which code. Written in cancho, no C and no foreign call; working name.

Capability tokensA chain of signed blocks that can only narrow. The token is the password; a statement outside it never reaches PostgreSQL.
Effect-checkedEvery statement is parsed, lowered to an IR and its effects checked against the token first. A refusal carries a rule tag.
Signed logOne Ed25519-signed, hash-chained commit per transaction, durable before PostgreSQL commits.
Branches, AS OF, mergeFork a branch, read a table as any past commit left it, merge three-way by key.

Check it yourself

Three levels of verification, each by a verifier that needs nothing but SHA-256 and Ed25519 (and the specs):

  • L1, integrity: is the log intact, in order, and not cut short? commit.md
  • L2, authority: was each commit allowed by the token it presented, and do its recorded effects equal what its statements do? token.md, ir.md
  • L3a, delta replay: is the data the history of the facts the log commits to, and do the tables hold exactly what the row changes say? l3a.md
$ ./verify vectors/ok_chain3.log
ok commits=3 branches=1
$ ./verify vectors/seq_skips.log
reject rule=seq-gap record=1
$ ./l3averify log --deltas deltas.tsv --live-dump live.tsv
ok commits=15 facts=19 branches=2 final

Each verifier exists more than once, written from the spec alone, and they must agree on every golden vector: cancho, Python, Go (L1 and L2) and a separate agent's reading (L3a). Mutation tests make sure a check that is removed is noticed.

Use it

$ proxy 5440 127.0.0.1 5432 main $ROOT postgres postgres ./log ./signing.key
$ psql -h 127.0.0.1 -p 5440 -U agent -d main -c "select cancho_fork('feature')"
$ psql -h 127.0.0.1 -p 5440 -U agent -d feature       # the database name is the branch

psql, psycopg 2 and 3, pg8000, asyncpg and node-postgres connect with a capability token as the password. The SQL is a subset (no subqueries, CTEs, set operations or window functions); claims.md lists what is claimed, what each claim rests on, and what is not claimed.

Status

  • M0 spec and verifiers (L1, L2, statement IR): built.
  • M1 the proxy in front of PostgreSQL: built.
  • M2 row-change capture, branches, AS OF, merge: built. The replay verifier (L3a) is built in Python and cancho with a third independent reading; Erasure is built except one step: salted row hashes, statement constants kept as erasable payloads, and cancho_erase through the proxy, which still verifies afterwards; the proxy does not yet rewrite its own statement store (an offline tool does). Recording bound values and snapshots are not built.
